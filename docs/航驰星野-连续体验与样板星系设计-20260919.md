## 1. 交付目标与现状证据

把已可用的探索功能组织成一个有尺度、有方向、与个人网站相连的宇宙。结构继续是「人物 → 星空 → 经历星系 → 项目星体」，保留向下浏览「履历 → 作品」。第一轮以**连续转场 + 字节跳动样板星系 + 物料生成 Agent 阅读闭环**为边界。其他星系继续可访问，暂不全部重做。

## 2. 美术方向：蓝色深空中的有形空间

首屏保持现在的人物、文字和蓝色基调。更宏大来自云体边界、遮挡和空白，不是继续均匀提高曝光。蓝色主导，紫色只留在少数阴影过渡；暖色集中在恒星、船灯与项目的局部受光边缘。

| 空间层次 | 形态与光线 | 运动规则 |
|---|---|---|
| 近景 | 稀疏、偏暗、轮廓不规则的尘埃；避开人脸和主要文字 | 随镜头产生明显视差，只在局部掠过，不用整屏黑幕遮转场 |
| 中景 | 一条有缺口的主蓝色云脊；受光薄边、内部暗核，能记住其轮廓 | 缓慢流动，整体形状稳定；转场时保持地标朝向 |
| 远景 | 深蓝黑空域和大小、亮度不均的星点，留出真正暗区 | 大部分稳定，少数亮星轻微变化；不铺满等亮粒子 |
| 项目与飞船 | 明暗交界、局部反射、粗糙度差异；轮廓受同一主光约束 | 飞行依靠物体视差和尾焰响应表达速度，不依靠全屏模糊 |

当前星云确实是动态密度场，而不是一张直接贴出的背景图。但它在远处有限体积内绘制，未读取场景深度；不能直接宣称它能正确遮挡任意近处飞船或星体。首轮少量近景尘埃应使用可参与深度关系的几何/局部体积代理，并检查透明排序。全场景深度融合体积云留待性能测量后决定。

NASA/ESA 作为此前选定的审美来源，本轮不新增外部图例、不宣称重新观看视频。现有素材继续保留署名。所有“空间隐喻”是设计表达，不是天文学模拟或真实业务设施。

## 3. 探索循环

**看见地标 → 选择方向 → 自由飞行或星图领航 → 接近项目 → 阅读故事 → 记录查看 → 继续探索或返回。**

进入后，字节星系作为默认建议方向，不自动强迫前往。星图始终可达；在星图中增加现有项目的直接阅读入口，使不想飞行的人也能读内容。自由操控可随时打断领航。抵达点位于可看到项目群的安全外侧，不把船停在某颗星体表面前。

按下推进有渐进加速，松开保留短距离滑行；制动必须明显且可预期。转弯滚转用缓动衔接，停止转向后自然回正。首轮目标：普通巡航下制动约 1 秒内降至原速度的 10% 以下，靠近项目自动降低最高速度；具体制动距离在调参后记录，不提前宣称手感已达标。

打开阅读时清除输入并平滑停车；阅读时暂停物理。关闭后恢复背后镜头，停在原安全位置，等待新的输入，避免读完突然滑走。查看记录直接复用已有进度，名称改为“已查看 / Viewed”；两颗待补充项目继续明示占位。

星尘、穿环与隐藏发现保留为支线，不挡主航线，不要求先完成挑战才能阅读。首轮只回归验证其可用性，不增加任务、资源、战斗或落地。

## 4. 五个星系的空间结构

共享蓝色宇宙、光照规则与排版，但不能共享完全相同的环形摆球。下面是设计提案，不是已实现状态。星系名、时间、职位继续引用已有履历数据。

| 星系 / 现有星体 | 远处看到什么 | 靠近发现什么 | 与真实经历的关系 |
|---|---|---|---|
| 字节跳动 / 5 个真实项目 | 偏斜的新月状蓝色云脊，缺口中一束暖光；一侧密、一侧空 | 项目分成前后两簇：生成与质检在前，模型迁移、多模态审核、绩效质检在深处；高低错落，无完整展示环 | 对应内容生成、内容判断与质量治理。路线从可感知的业务产物进入背后的工程方法 |
| 开源探索 / dsh-lark-bridge、trae-to-lark | 两条隔空相望的细长云带，夹着开阔通道 | 两颗主体通过轻微弧形尘埃呼应；连接线只在选中时短暂提示 | 对应飞书与 Coding Agent 的桥接；不是虚构网络流量或使用规模 |
| 现代汽车 / AI 音乐壁纸 | 一片倾斜、舒展的透光薄弧，主星体单独落在弧内 | 一颗重点星体，周边少量缓慢波纹与柔光；界面呈现产品规划到概念验证的故事 | 对应智能座舱的感官体验与 AI 音乐壁纸，不暗示量产上线 |
| 崇振时代 / 1 颗待补充 | 错落的数道短云脊围出一个未闭合空间 | 保持一个明确“项目资料待补充”的入口；可阅读已知实习职责，不伪造项目细节 | 对应多 Agent 内容产品、AI 辅助设计工作流；仅使用履历已有描述 |
| 大连理工 / 1 颗待补充 | 大范围稀疏星群与安静的偏心环弧，亮度克制 | 一颗校内经历入口、更多留白；待补充标记清晰 | 对应自动化本科阶段；留白承认资料缺口，不编造科研或获奖 |

主航线从开场斜向字节云脊，其他地标分布在不同方向与深度。首次进入不应像星图一样把五套结构平铺在同一视野。星图承担“看全局”，世界视角承担“身在其中”。不机械放大全部坐标；先校准可见角尺寸、航行时间与空间间隔。

## 5. 人物、飞船与镜头分镜

### 镜头语言与最小架构调整

同一个 Canvas 中保留共同天空、主光和后处理；一个镜头控制器负责首页、离场、巡航、阅读和返回，每帧只有一个相机写入者。原首页滚动动画只在首页取得控制权。飞行动力学保留，镜头跟随与物理更新分开。

用同一进度驱动人物、飞船、相机、文字与地标揭示，结束事件移交控制，替代 App 的墙钟定时器与 Flight 的独立入场计时。保存首页的 position、quaternion、FOV、scrollY 与焦点；保留星云时间与固定种子，不在模式切换时重建背景。主要云体不再随探索状态改变密度布局，只允许轻微曝光补偿。

人物和船在转场期间共同存在。通过镜头后退让人物视觉缩小，避免把胸像直接缩成漂浮摆件。胸像截断边缘先留在画面下缘，随后进入局部暗尘埃遮挡区并渐隐；必须在侧视和窄屏检查底边。若当前模型不能完成这段构图，再小范围补衣服下缘，暂不重做全身。

### 完整样板体验（时间为提案）

| 阶段 | 画面与运动 | 用户状态 / 验证重点 |
|---|---|---|
| 首页 / 静候 | 保留认可的肖像；肩部远处只有不抢眼的蓝色云脊缺口，代表后续字节方向 | 下滑履历照常；探索按钮为文字与细线 |
| 0–0.5 秒 / 启动 | 标题与边缘信息淡出；背景不断流，人物不突然下坠 | 锁定飞行输入，可使用返回；无全屏闪白 |
| 0.5–2.0 秒 / 拉远 | 镜头沿后上方平滑退开，人物缓慢变小；主云脊一直可追踪 | 人物底边保持在画框或局部尘埃中，不露硬切胸像 |
| 2.0–3.3 秒 / 船显现 | 飞船从画面下方的暗处显现，先见受光船脊再见完整剪影；人物在前方渐隐 | 船保持固定物理尺寸，不从零缩放弹出；避免解释成人物变成飞船 |
| 3.3–4.5 秒 / 就位 | 镜头稳定在船后上方，字节云脊位于前方偏侧；尾灯启动 | HUD 逐层出现，速度为零，镜头完成后开放控制 |
| 约 10–20 秒 / 前往字节 | 用户手动推进或选择星图领航；近尘埃掠过，云脊逐渐拉开，项目群从遮挡后露出 | 这是调校目标而非强制等待；随时接管、开星图或返回 |
| 接近 / 项目聚焦 | 一颗较大的物料生成项目星体进入主要构图，另四颗形成不同深度背景 | 同时只突出一个项目入口；星体主体不被卡片覆盖 |
| 阅读 / 不限时 | 停船，镜头轻微调整后保持；阅读层从稳定的深蓝底上出现 | 标题、职责、业务问题、四步方法、结果清楚；不强制观看动画 |
| 关闭 / 约 0.6 秒 | 阅读层退去，镜头回到船后，保留刚读的星体作为空间参照 | 恢复焦点；速度为零，输入后继续飞行 |
| 返回 / 约 2 秒 | 从当前姿态缓慢收束至返程方向，船移出下缘；共同星空中肖像淡入并放大 | 不倒放漫长航程；人物未遮住画面前避免直接重定位；恢复首页视角与滚动位置 |

返回不是强行在两秒内高速穿过所有星系。采用明确但柔和的镜头过渡；远处返回时允许在局部遮挡阶段重定位，需确认不会出现背景重置或地标瞬移。减少动态模式用不超过 0.3 秒的淡化切换、固定视角，停止自动环绕与加速 FOV 变化；这是一条独立可验收路径。

### 样板内容表达

物料生成 Agent 正文已具备真实问题、职责、方法与定性结果，适合首轮。阅读顺序：商业增长团队的重复包装工作 → 自己独立负责的范围 → 素材处理、案例叙事、模板回填、质量校验 → 模型语义与确定性代码分工 → 来源分级与人工确认门 → 已有定性成果。

四个步骤可以画成一张细线流程图，标注“方法示意”；不把它们做成四颗额外项目星体。当前没有可核验的节省百分比、界面截图或业务演示，不填造数字，不制作冒充真实产品的截图。

### 飞船规则

先保留现有程序模型，修成低矮、前后方向明确的轮廓：较长船脊、收敛的翼尖、较小驾驶舱、两个可辨尾灯。蓝灰哑光主体与人物衣服呼应，少量金属边缘承担高光；尾焰面积缩小、亮度随推进改变，静止只留弱光。先用无材质剪影检查方向，再看受光，不以增加面数掩盖比例问题。

## 6. UI：让文字帮助定位

首页入口继续采用已认可的简洁文字。探索常驻只保留返回、星图、语言/设置，以及必要方向信息。飞行指南首次进入短暂提示，之后收起；航速在推进或制动时更明显，静止弱化；收集提示短暂出现，不抢占主要地标。

远处只显示当前建议目的地或用户选中的地标；靠近后显示星系名；项目入口按距离、屏幕可用空间与选中优先级出现。桌面同屏至多三个简短项目名、一个完整交互提示；手机只展开一个。标签使用细引线、稳定文字底部暗衬，避免每颗球挂一个大毛玻璃卡片。重叠时隐藏次要标签，不能压缩成逐字竖排；星图仍提供完整目录。

桌面项目正文采用稳定深蓝底、足够行距和清楚层级，可保留薄边；手机使用占满可读区域的阅读页，关闭按钮始终可见。点击目标至少 44×44 CSS 像素。键盘焦点可见，弹窗保持焦点约束并正确返回，触控提示不出现 F/WASD。中英文共用信息层级，长标题允许两行，英文学校名与履历统一为 Dalian University of Technology。

## 7. 技术约束、实施边界与资产

继续 React + TypeScript + R3F + Three.js，无后端、无引擎替换。前端命令在 web/ 执行。保留现有未提交工作，实施前本地留档；未经确认不提交、推送或部署。

### 首轮实施顺序（确认后才开始）

1. 保存现状，统一相机与转场状态；共同背景、人物与飞船交接、返回、减少动态路径。先验收这段镜头，再进入空间美术。

3. 完成标签分层、星图直接阅读入口、手机提示、阅读停车和恢复；按真实正文增加方法示意，保留八个真实项目和两颗占位。
4. 回归完整流程与已有支线，构建、检查、相关测试和实际画面验证；记录性能后决定降低哪些装饰成本。

首轮不包括全身人物重建、五星系全面资产替换、落地、战斗、新收集系统、新剧情、全屏体积云深度管线重写。后续第二阶段扩展其余四套空间形态；第三阶段依据样板效果选择是否替换飞船、补真实项目图与优化高级云气。

实施后记录设备型号、芯片/GPU、系统、浏览器、视口、DPR、画质、构建模式与测试路线。在 production preview 预热后，各录制 60 秒：首页、入场后巡航、字节密集区域；至少测桌面及一台真实手机，窄屏模拟不能替代。暂定桌面普通画质 p95 帧时间 ≤22ms、手机低画质 ≤33ms，作为调优目标；没拿到实机时明确标记手机性能未验收。记录加载体积、最长卡顿、是否 WebGL 丢失，未达标则减少装饰再复测。

## 8. 验收标准

以下均为下一轮实施后的验证要求，不是本轮已完成声明。

- [ ] 首屏与探索能认出同一条主云脊和同组参考亮星；暂停对比进入前、中、后三帧，地标相对方向连续，不因模式切换整批弹出。
- [ ] 普通模式入场约 4.5 秒、返回约 2 秒；录屏逐帧检查人物底边、模型交接、相机朝向与 FOV，无单帧复位或明显曝光跳变。
- [ ] 转场每帧只有一个相机控制源；切后台再返回不会跳过模型交接；重复进入返回五次不残留输入或重复 HUD。
- [ ] 样板远处能凭新月云脊辨识，接近后五项目前后错落；关闭标签仍可区分字节与其他星系的主要轮廓。
- [ ] 完成进入 → 星图领航字节 → 打开物料生成 Agent → 关闭 → 手动飞行 → 返回；航行中可接管，无需收集即可阅读。
- [ ] 制动约 1 秒降至巡航速度的 10% 以下；星体附近限速有效；阅读结束无意外漂移，重开不改变项目归属。
- [ ] 桌面 1280×720、手机尺寸 390×844 检查中英文；项目提示不交叠、不逐字竖排、不挡返回和星图；手机按钮至少 44px，提示匹配触控。
- [ ] 键盘焦点可见，弹窗关闭后焦点恢复；减少动态模式无自动环绕、星光呼吸、云流和加速视角拉伸，仍能完整探索与阅读。
- [ ] 八个真实项目与两颗待补充保持正确；四步方法只作示意；不新增无来源的业务数字；“已查看”仅记录已打开的真实项目。
- [ ] 低画质下地标、项目及双语功能不缺失；手机实机、性能条件及未通过项如实记录。
- [ ] 在 web/ 执行 build、lint、test；必要时为相机状态交接、暂停/恢复与进度兼容增加有实际边界意义的测试；完成实际画面验证。
